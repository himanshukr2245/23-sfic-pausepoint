- 2026-10-07 — hk:init = markers + variants, not code generators: every combination is the template minus lines/files, so the template itself builds and passes every gate; module edge-gate work is a list of steps (EDGE_STEPS) so the middleware reads the same with or without auth. - 2026-10-07 — Sync conflicts: last write wins by edit time, enforced in the browser (pull) AND in the database (a trigger keeps the newer row when an older edit arrives late); deletions are tombstones with the text wiped. A test caught a phone overwriting a newer laptop edit before the trigger existed.
- 2026-10-07 — Auth calls (sign in, sign up, reset, email-link verify) go from the browser to Supabase Auth, not through Server Actions: Supabase's per-IP rate limits and CAPTCHA then see the real person. Identity on the server = getClaims(); data = RLS.
- 2026-10-07 — Sign-in, sign-out and account deletion end with a full page load (lib/reload-to.ts): nothing of the previous person stays in memory on a shared phone. The synced store resolves the person once per page load.
- 2026-10-07 — The header account button is client-side: the service worker saves pages without cookies, so a server-rendered "Account" link would be wrong on cached pages.
- 2026-10-07 — Email links land on a page with a button (mail scanners open links ahead of people; a link used on GET would be burnt).
- 2026-10-07 — Service worker is hand-written (public/sw.js, ~100 lines), not Serwist: small enough to read in full, no build plugin to keep in step with Turbopack. Precache is anonymous (credentials omitted) so a person's page is never saved for the next person on a shared phone.
- 2026-10-07 — Pages are network-first with a 4 s limit: a near-dead connection opens the saved page instead of a spinner.
- 2026-10-07 — Playwright workers = logical cores / 4 (1–4): 4 browsers running axe beside `next start` overloaded the 8-thread laptop; 2 workers ran faster and never flaked.
- 2026-10-07 — zod only through `src/lib/zod.ts` (zod/mini, `export * from`, `jitless`), enforced by ESLint: the notes chunk went from 95 KB to 20 KB gzip, and zod's eval probe no longer fires a CSP violation.
- 2026-10-07 — Notes live in IndexedDB (the offline module's device store). Core-only has no notes (a store that forgets on reload would be a false claim). `src/lib/notes/active.ts` is the one place that picks the store.
- 2026-10-07 — CI (`.github/workflows/ci.yml`, from HK_KIT) repeats Workers Builds on Linux before Cloudflare does, because a Windows laptop cannot reproduce Linux npm's dependency tree (two failed deploys). After every push: `npm run check:live -- https://starter.hkr.dpdns.org --expect-head`.
- 2026-10-07 — `esbuild` is a direct devDependency (^0.27, the range @opennextjs/cloudflare is tested with) because OpenNext imports esbuild without declaring it; on Workers Builds the only top-level copy was Vite's optional peer, which npm does not install → "Cannot find package 'esbuild'". - 2026-10-07 — `prepare` tolerates a missing git repo (`|| echo …`) so `npm install` works from a ZIP download or a Docker build without .git.
- 2026-10-07 — ESLint ignores generated folders (.open-next, .wrangler, coverage, Playwright output); a local OpenNext build otherwise floods lint with bundled code.
- 2026-10-07 — The Top Loader starts from Next's `onRouterTransitionStart` (src/instrumentation-client.ts), not a document click listener, because <Link> always calls preventDefault() (the bubble-phase listener skipped every Link click) and a click listener never sees router.push or Back. The component decides "real page change" against the page it last rendered (on Back the browser has already changed location). A 300 ms minimum display makes instant navigations visibly register. Proven by e2e/top-loader.spec.ts.
- 2026-10-07 — package-lock.json is written with npm 10.9.2 (`npm run lock`), the npm Cloudflare Workers Builds runs, because a lock from local npm 11 was valid here and rejected there ("Missing: @emnapi/runtime … from lock file"). Guarded by scripts/verify-lock.mjs in the pre-commit hook (only when the lockfile is staged) and in check:release. Revisit if: Workers Builds moves to npm 11 — then change hk.config.json deploy.npmVersion.
